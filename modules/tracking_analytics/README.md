# modules/tracking_analytics — Vehicles, Tracking & Traffic Analytics (Person 4)

The vehicle-intelligence layer of the Road Intelligence system: vehicle
detection → multi-object tracking → traffic analytics → alerts → Road Health
Score.

```python
from modules.tracking_analytics import TrackingAnalytics

analytics = TrackingAnalytics("models/vehicle_detection_yolov8n.pt")
result = analytics.process(frame)     # .predict(frame) is an alias
```

`result` is a shared-schema `FrameResult` dict. This module fills **`tracks`,
`alerts`, `analytics`** and leaves `detections` / `segmentations` empty so
`shared.schemas.merge_frame_results()` can concatenate it with Person 1/2/3's
output without duplicating boxes.

> **Stateful, unlike the other three modules.** Tracking needs frame history.
> Call `analytics.reset()` between videos or streams.

---

## Pipeline

```text
Dataset (none trained — pretrained COCO weights)
      ↓
Preprocessing (Ultralytics letterbox; boxes rescaled back to original frame)
      ↓
Training (NOT PERFORMED — see "Training" below)
      ↓
Validation / Testing (tracking + analytics layer, synthetic + real video)
      ↓
Model (YOLOv8/YOLO11 COCO checkpoint, filtered to 6 road-user classes)
      ↓
Inference (TrackingAnalytics.process(frame))
      ↓
Output Schema (shared FrameResult: tracks / alerts / analytics)
      ↓
Integration (merge_frame_results + fill condition counts from other modules)
```

## Dataset

**No dataset was collected, annotated, or trained on by this module**, by
design: the spec says this module "should NOT unnecessarily train a new
vehicle detector".

| Item | Value |
|---|---|
| Detector training data | MS COCO (via the pretrained Ultralytics checkpoint) |
| COCO license | Images: Flickr terms, per-image. Annotations: CC BY 4.0. |
| Ultralytics YOLOv8/YOLO11 weights license | AGPL-3.0 (see limitations below) |
| Dataset size used here | None — zero images downloaded, labelled or trained on |
| Train/val/test split | Not applicable (no training run) |

Evaluation data used for the tracking layer is **synthetic** (scripted
trajectories generated by `evaluation.py`) plus any video the team supplies
via `--video`. No public tracking benchmark (MOT17, etc.) has been run, and
none is claimed.

## Class mapping

COCO labels are never returned. `class_mapping.py` maps them to
`shared/classes.yaml` names:

| COCO | Normalized | Counts as vehicle? |
|---|---|---|
| `car` | `car` | yes |
| `truck` | `truck` | yes |
| `bus` | `bus` | yes |
| `motorcycle` | `motorcycle` | yes |
| `bicycle` | `bicycle` | yes |
| `person` | `person` | **no** — reported as `person_count` |

**Excluded and documented, not force-mapped:** `train`, `boat`, `airplane`,
`traffic light`, `stop sign`, `fire hydrant`, `parking meter`, `bench`.
`traffic light` is excluded deliberately — COCO gives the box, not the
red/green *state*, and the spec forbids claiming red-light violation
detection without a reliable state detector.

Filtering happens inside YOLO via `classes=` (`allowed_model_class_ids()`),
so irrelevant categories never pollute NMS.

## Training

None. Transfer learning was not needed because COCO already covers all six
road-user classes at production quality.

If the team later decides a custom vehicle detector is warranted (e.g. for
Egyptian traffic, tuk-tuks, or heavy night-time use), nothing here needs
rewriting: any object exposing `detect(frame) -> list[detection dict]` can be
injected:

```python
TrackingAnalytics(config=cfg, detector=MyCustomDetector(...))
```

## Validation & testing

| What | How | Result |
|---|---|---|
| Schema conformance | `shared.schemas.validate_frame_result()` on every emitted frame | 45 tests pass |
| Class normalization | Every track class asserted ∈ `classes.yaml` | pass |
| ID stability | Scripted linear motion, 30 frames | no ID switches |
| Occlusion recovery | Detection gap injected mid-track | ID retained within `max_age` |
| Speed accuracy | Simulated ground truth + exact homography | 0.0 % MAPE clean; 5.27 % MAPE with 3 px box jitter |
| Analytics throughput | 300 frames, detector excluded | ≈3.2k–3.4k analytics FPS |

Measured figures live in `evaluation_results.json` and are reproducible with:

```bash
python -m modules.tracking_analytics.evaluation --synthetic
```

Two tests are skipped unless `ultralytics` is installed — they are the only
ones that load real weights. **Detector accuracy (mAP) is not reported here**
because this module trains no detector; use the Ultralytics model card for
the checkpoint in use.

## Cross-module counts and the Road Health Score

`road_damage_count`, `obstacle_count`, `speed_bump_count` and the Road Health
Score describe **road condition**, which this module cannot observe. They are
computed from the other modules' findings, passed in per frame:

```python
tracking_result = analytics.process(
    frame,
    other_results=[damage_result, segmentation_result, obstacle_result],
)
```

Without `other_results` the counts stay `0` and the road-health fields are
`None` with an explanatory note — never a fabricated score of 100.

`road_health_score` = `max(0, 100 − count_penalty − area_penalty)`, using the
weights in `shared/config.py:ROAD_HEALTH_WEIGHTS` (overridable per scene).
It is a **project-defined road condition indicator, not an official
civil-engineering road safety certification** — that disclaimer ships in the
output itself (`road_health_basis`) and in the overlay.

## Configuration

Nothing is hard-coded at a call site. Shared thresholds come from
`shared/config.py`; per-scene geometry (counting lines, direction zones,
camera calibration) lives in a YAML file:

```python
from modules.tracking_analytics import TrackingAnalytics, TrackingAnalyticsConfig

config = TrackingAnalyticsConfig.from_yaml("scene_config.yaml")
analytics = TrackingAnalytics("models/vehicle_detection_yolov8n.pt", config=config)
```

`config=` also accepts a plain dict or a shared `InferenceConfig`, per the
shared contract. See `scene_config.example.yaml` for a commented template.

### Direction convention

Angles are degrees with **0° = image right, 90° = image up** (the y-axis is
flipped when computing angles, because image y grows downward). A vehicle
travelling toward the top of the frame has `direction_deg ≈ 90`.

### Speed estimation

| Calibration supplied | Output |
|---|---|
| None | `velocity_px_s` only; `estimated_speed_kmh: null` |
| `pixels_per_meter` (uniform scale) | `estimated_speed_kmh` with `speed_reliable: false` + a `RuntimeWarning` — perspective is ignored |
| 4 image↔world point pairs (homography) | `estimated_speed_kmh` with `speed_reliable: true` |

Pixel velocity is **never** relabelled as km/h. The field is
`estimated_speed_kmh` — always an estimate, never a calibrated instrument
reading.

## Tracking backend

`tracker.backend` may be:

- `"native"` (default) — self-contained ByteTrack-style associator: two-stage
  high/low-confidence association, IoU matching with linear motion
  prediction, class-consistency voting. Pure NumPy, no extra dependencies, so
  the module works in a clean environment.
- `"ultralytics"` — delegates ID assignment to Ultralytics ByteTrack/BoT-SORT
  when installed. Trajectory, velocity, analytics and alerts are unchanged.

## Integration

```python
from shared.schemas import merge_frame_results

final_result = merge_frame_results(
    damage_result, segmentation_result, obstacle_result, tracking_result,
    frame_id=frame_id, timestamp=timestamp,
)
```

Two notes for whoever wires up the dashboard:

1. Run `analytics.process(...)` **last** and pass the other three results as
   `other_results`, so condition counts and road health are real. Because
   `merge_frame_results` lets later results win on analytics keys, the
   tracking result should also be the last argument in the merge.
2. Call `analytics.reset()` when the user loads a new video.

## Known limitations

- **No detector metrics.** Accuracy is whatever the chosen COCO checkpoint
  achieves; unusual vehicles (tuk-tuks, animal carts, heavily modified
  trucks) are common in some regions and are outside COCO's distribution.
- **car/truck flicker.** A known COCO weakness on large SUVs and vans.
  Majority-vote class stabilisation reduces but does not eliminate it.
- **Motorcycle riders double-count.** Rider and motorcycle are two separate
  COCO objects; counts are per-object, not per-road-user.
- **Speed needs calibration.** Without a homography, no real-world speed is
  emitted at all. With one, accuracy depends far more on calibration quality
  and box jitter than on the arithmetic here — treat all speeds as estimates.
- **Wrong-way needs configuration.** With no direction zone configured the
  detector is inert (`wrong_way_configured: false`); it never guesses the
  legal direction of travel.
- **Alerts are unverified signals.** Every alert carries `verified: false`.
- **Tracking is 2D and appearance-free.** Long occlusions, dense congestion,
  and camera motion cause ID switches. No re-identification model is used.
- **Density thresholds are project-defined**, tuned on synthetic data only;
  they should be re-tuned per camera.
- **AGPL-3.0.** Ultralytics weights and the `ultralytics` package are
  AGPL-3.0. Fine for coursework; a commercial deployment needs either an
  Ultralytics license or a differently-licensed detector. Swapping detectors
  requires no change to this module.
